# Dynamic Ranchi route evidence API — Phase 5D Stage 2

`POST /pilot/ranchi/route-evidence` exposes the unchanged Stage 1 offline analyzer.
It accepts one route geometry and returns mapped context from the verified local
Ranchi snapshot. `POST /route`, `GET /pilot/ranchi/comparison`, their models and
their behavior remain unchanged. No frontend changes are included.

## Local startup, without downloads or provider access

Run from `D:\shepath` in PowerShell. This workspace's backend environment contains
FastAPI 0.142.2 and Pydantic 2.13.5 but does not contain the geographic packages.
The existing Stage 1 environment has their tested Python 3.11 Windows builds.
The following process-local path setting makes those local packages available;

Use a dedicated terminal for that setting. It replaces that terminal's existing
PYTHONPATH, if any. Both existing environments use compatible CPython 3.11 Windows
packages. Do not reuse compiled site-packages across incompatible Python/OS builds.
For a self-contained deployment, `backend/requirements.txt` now declares
`shapely==2.1.2`, `pyproj==3.7.2`, `osmium==4.3.1` alongside the existing backend
dependencies. Provision these into the backend environment using approved local
wheels; then omit the PYTHONPATH setting. No installation was performed in this stage.
osmium is needed because the reused verifier imports it, even though requests do
not parse the regional PBF. Keep the verified small pilot artifacts and Stage 1
Python files in their repository-relative locations.

The new endpoint needs no HeiGIT key or other network service. Existing live
navigation retains its existing provider configuration requirements. `/health`
still reports backend health, not evidence-dataset readiness: dataset loading is lazy.
Do not start with `--lifespan off`; that produces an explicit evidence service error.

## Request and response

```powershell
$request = @{
  route_id = 'new-ranchi-route'
  coordinates = @(@(23.355, 85.32), @(23.36, 85.32))
  distance_metres = $null
  duration_seconds = $null
} | ConvertTo-Json -Depth 5
$evidence = Invoke-RestMethod -Uri 'http://127.0.0.1:8011/pilot/ranchi/route-evidence' -Method Post -ContentType 'application/json' -Body $request
$evidence.status
$evidence.route.geometry_sha256
$evidence.route_context.categories.healthcare_facilities
```

Coordinates are ordered **[latitude, longitude]**, not GeoJSON order. Distances
and durations are optional, finite nonnegative caller metadata; they do not
replace the actual geometry denominator. Unknown fields are rejected. The
buffer is fixed at **100 metres** and is not a request parameter. `route_id`
must be a nonblank string of at most 256 characters. Numeric strings and
booleans are not accepted as coordinates or metadata.

Both supported and unsupported coverage return HTTP **200**, with the complete
Stage 1 response. No wrapper, rounding, score or field removal is introduced.
Representative projections of the responses (other fields omitted here only):

```json
{
  "schema_version": "SHEPATH.dynamic_route_evidence.v1",
  "status": "available",
  "analysis": {"buffer_metres": 100.0},
  "coverage": {"centerline_fully_covered": true, "full_buffer_covered": true},
  "evidence_completeness": {"status": "mapped_snapshot_analyzed", "real_world_completeness": "unknown"}
}
```

For `{"route_id":"outside","coordinates":[[0,0],[1,1]]}`, the returned
projection is:

```json
{
  "schema_version": "SHEPATH.dynamic_route_evidence.v1",
  "status": "coverage_unavailable",
  "route_context": null,
  "coverage": {
    "bbox_south_west_north_east": [23.335059, 85.308481, 23.38, 85.34],
    "centerline_fully_covered": false,
    "full_buffer_covered": false,
    "reason": "centerline_outside_pilot"
  },
  "evidence_completeness": {"status": "not_analyzed_coverage_unavailable"}
}
```

Full geometry/evidence hashes, source hashes, snapshot timestamp, selected original
OSM geometries, missingness, denominators, uncertainty and duplicate sensitivity
remain intact. See the [Stage 1 contract](../../data/ranchi_safety/DYNAMIC_ROUTE_EVIDENCE_SCHEMA.md)
and [full saved-route example](../../data/ranchi_safety/dynamic_validation/heigit-foot-walking-route-1.json).
All successful/error responses generated by this adapter use `Cache-Control: no-store`;
FastAPI's standard model-validation responses retain FastAPI defaults.

| HTTP status | Meaning |
|---|---|
| 200 | `available` **or** normal `coverage_unavailable`; inspect `status` |
| 400 | Malformed Content-Length |
| 408 | Request body did not arrive in 10 seconds |
| 413 | Body exceeds 1 MiB, checked before JSON parsing, including chunked bodies |
| 415 | Compressed body unsupported; send uncompressed JSON |
| 422 | Invalid JSON, coordinates/metadata, stationary route, submitted vertex limit, or Stage 1 densification limit |
| 503 | `dataset_unavailable`, `analysis_busy`, `analysis_failed`, uninitialized or stopping service |
| 504 | Analysis response deadline exceeded |

Service-error example:

```json
{"detail":{"status":"service_error","code":"analysis_busy","message":"One analysis is already running in this worker. Retry later."}}
```

Busy errors include `Retry-After: 5`. Model-validation errors use FastAPI's standard
`detail` list; other adapter errors use a `detail` object with `status/code/message`.
Do not interpret an error or unavailable coverage as zero facilities.

## Lifecycle, CPU work and safeguards

Each ASGI worker owns one `EvidenceService`, one lazily started executor thread
and one successfully loaded dataset. A nonblocking admission lock allows **one
job total, including initialization**, with **no waiting executor queue**. All
competing submissions immediately receive 503; no per-request threads or process
pools are created. Loading, geometry analysis, response validation and JSON
serialization all run in that thread outside the async event loop. Pure Python
portions still share the GIL; this is workload isolation, not unlimited CPU capacity.

First use verifies and projects the small pilot exports, then retains that snapshot.
There are no warm per-request source reads or regional index/PBF reads. Failed
initialization is latched as a service error until worker restart, preventing
repeated corrupt-file scans. Repair missing dependencies/artifacts and restart;
never substitute an empty dataset. A loaded snapshot is intentionally not watched
for subsequent disk changes. Updating sources requires a verified pin change and
restart. Stage 1 source and code hashes are preserved unchanged.

The analysis response deadline is **60 seconds**, including cold initialization
and serialization. An ordinary thread cannot safely be killed on timeout. After
504 or request-task cancellation, the existing job continues and **keeps its slot
until completion**; new work cannot pile up. Client disconnection does not imply
instant computation cancellation. Shutdown cancels pending work but cannot
forcibly stop a running thread; a stuck native call requires worker/process
supervision. No output is truncated to meet the deadline. This is a response
deadline and concurrency bound, not a hard CPU-time kill.

Body timeout is 10 seconds and body limit 1 MiB. The adapter retains Stage 1's
10,000 submitted and 50,000 densified vertex bounds. It rejects rather than
simplifies/truncates over-limit routes. Body middleware applies only to this new
path (including its trailing-slash redirect), so existing endpoints are unaffected.
Uvicorn's documented `--limit-concurrency 32` also bounds admitted HTTP connections;
under server-level overload its own 503 response can differ from adapter errors.
Multiple Uvicorn workers each have their own slot, thread and memory copy.

Stage 1 measured 7.25 MiB of local exports, 9.19 MiB retained and 57.55 MiB peak
Python-managed loader allocations, excluding interpreter and native GEOS/PROJ
memory. Allocate additional native and per-analysis memory; do not treat those
figures as a total worker ceiling. Full audit responses are hundreds of KB.

## Offline validation

```powershell
Set-Location D:\shepath
$env:PYTHONPATH = 'D:\shepath\data\ranchi_safety\.pbf_venv\Lib\site-packages'
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
Push-Location data\ranchi_safety

Pop-Location
```

Tests exercise HTTP success/coverage, strict validation, geometry identity, one-time
loading, actual manifest-pin rejection, missing/corrupt sources and missing dependencies,
body size/read timeout, concurrency admission, request cancellation, analysis timeout
with retained capacity, and existing navigation/comparison contracts. Saved-route
tests compare the entire endpoint JSON to each Stage 1 persisted result, including
all hashes, metadata and nested evidence. TestClient invokes the real ASGI stack
in-process; it does not call routing providers or require a listening server.

Validation on 2026-10-10: **39 backend tests passed** (27 existing, 12 new) and
**80 offline regression tests passed**. No failures or skips remain. The three
saved routes matched their complete Stage 1 JSON exactly. The backend suite took
36.54 seconds; the offline suite took 58.15 seconds while running concurrently.
Observed HTTP timings were 9.17 seconds for route 1 including cold loading,
3.58 seconds for route 2 and 7.17 seconds for route 3. These include in-process
HTTP and JSON overhead under concurrent test load, not a production throughput
benchmark. Source hashes and geographic calculations did not change.

The backend log is [ROUTE_EVIDENCE_BACKEND_TESTS.log](ROUTE_EVIDENCE_BACKEND_TESTS.log).
It is UTF-8/LF text. Windows PowerShell 5 `Tee-Object`/redirection can produce
UTF-16 and formatted line padding, so capture future transcripts directly instead.
From the repository root, after configuring the local dependencies above:

```powershell
@'
import os, subprocess, sys
from pathlib import Path
run = subprocess.run(
    [sys.executable, '-m', 'unittest', 'discover', '-s', 'backend/tests', '-v'],
    stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
    env={**os.environ, 'PYTHONIOENCODING': 'utf-8'},
)
transcript = run.stdout.decode('utf-8').replace('\r\n', '\n')
transcript = '\n'.join(line.rstrip(' \t') for line in transcript.split('\n'))
Path('backend/docs/ROUTE_EVIDENCE_BACKEND_TESTS.log').write_bytes(transcript.encode('utf-8'))
print(transcript)
raise SystemExit(run.returncode)
'@ | .\backend\.venv\Scripts\python.exe -
```

Expected injected service failures log tracebacks during tests; these are passing
error-handling cases. The installed Starlette emits an existing httpx TestClient
deprecation warning; it did not prevent validation. No packages were fetched.

## Frontend integration considerations

Use the newly generated route's coordinates, not its label alone. Preserve both
coverage states, unknown values and uncertainty. Handle 503 busy and 504 with
bounded user-visible retry behavior. This service is ready for a frontend adapter
that supports those states; it does not provide evidence-based preference comparison
for arbitrary routes or replace the fixed saved comparison endpoint. Serializing
several route analyses is appropriate for the initial single-slot implementation.

Limitations remain the pilot boundary, historical snapshot, sparse attributes,
ambiguous establishments, unknown real-world completeness, unverified walked-street
attribution and unobserved activity/operating status. No safety judgment is supported.
Production throughput, hostile-client load and process-level hard timeouts need
separate deployment testing. Frontend files and Stage 1 calculations are unchanged.
