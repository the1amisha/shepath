# Static trip sharing

The live route overview includes **Share your trip plan**. Its expandable preview shows the exact text used by WhatsApp and the printable tab. Mock journeys do not offer this feature.

The text includes start/destination labels, the selected provider-order route name, estimated distance/time, departure date/time in IST, mapped business/healthcare counts and the longest facility gap where available. It also includes missing-tag context, source snapshot and geometry/evidence identifiers. With valid departure and covered evidence, it adds offline daylight and supported facility-hours summaries. Missing evidence, unsupported coverage and invalid departure never become zero counts or invented time assessments.

**Share on WhatsApp** opens an encoded `https://wa.me/?text=...` URL. The user chooses a recipient and sends the message in WhatsApp. Opening the preview does not send data. The message includes place names and route identifiers, so the interface asks the user to review it before sharing. There is no hosted plan URL, live tracking or turn-by-turn navigation.

**Open printable plan** opens a local tab containing a text snapshot and a **Print / save as PDF** button. The user chooses a printer or Save as PDF in the browser dialog. The tab has no external images, scripts, fonts or map tiles; it uses text nodes rather than HTML interpolation for user-entered place names. It remains printable without network access after opening. A blocked popup shows an actionable message. PDF output is generated by the user's browser, not a server.

Changes to selected route, departure or place labels update the panel. An already opened print tab or WhatsApp draft remains a snapshot; reopen it for an updated plan. Sharing and printing make no additional routing or evidence API requests. Historical mapped evidence is incomplete and is not a personal-safety assessment.

Validation: automated tests check text/URL fidelity (including Hindi and reserved characters), missing evidence, invalid time, updates, blocked popups and literal rendering of HTML-like text. Browser replay checks the printable tab, Ranchi summary, narrow layouts and absence of extra route/evidence requests. No backend or dependency changes.
